# user-service

`user-service` owns user registration, credential validation, password hashing, and JWT token creation. It persists users to PostgreSQL and is reached through `api-gateway` under `/api/users/**`.

## Runtime Role

- Listens on port `8081`.
- Registers with `eureka-server`.
- Imports database, Kafka, and JWT settings from `config-server`.
- Stores users in PostgreSQL table `users_schema.users`.
- Hashes passwords with BCrypt.
- Issues signed JWTs containing `userId` and `role` claims.

## Local Classes

### `UserServiceApplication`

Spring Boot entry class. It sets the JVM default timezone to `Asia/Kolkata` before starting the service.

### `UserController`

REST controller for `/api/users`.

Endpoints:

- `POST /api/users/register`: accepts `RegisterRequest`, calls `UserService.registerUser(...)`, returns `201 Created` with `UserResponse`, or `400 Bad Request` on validation failure.
- `POST /api/users/login`: accepts `LoginRequest`, calls `UserService.loginUser(...)`, returns `LoginResponse` with a JWT, or `401 Unauthorized` when credentials are invalid.

The controller is intentionally thin. It maps HTTP requests to service calls and converts service exceptions into HTTP responses.

### `UserService`

Business logic for registration and login.

`registerUser(RegisterRequest req)`:

1. Rejects passwords shorter than 8 characters.
2. Checks `UserRepo.findByEmail(...)` to prevent duplicate emails.
3. Builds a `User` entity.
4. Hashes the plaintext password through `PasswordEncoder`.
5. Uppercases the role.
6. Saves the entity with `UserRepo.save(...)`.
7. Returns a safe `UserResponse` that excludes the password.

`loginUser(LoginRequest req)`:

1. Looks up the user by email.
2. Uses `PasswordEncoder.matches(...)` to compare the submitted password with the stored hash.
3. Calls `JwtUtil.generateToken(...)`.
4. Returns `LoginResponse` containing the token.

### `UserRepo`

Spring Data repository interface for `User` entities. It extends `JpaRepository<User, Long>`, so Spring generates common CRUD behavior at runtime.

Custom finder:

- `Optional<User> findByEmail(String email)`: Spring Data parses the method name and generates a query against the `email` field.

### `User`

JPA entity mapped to `users_schema.users`.

Fields:

- `id`: primary key generated by the database.
- `email`: unique and non-null.
- `password`: BCrypt hash, not plaintext.
- `role`: user role stored as uppercase text.
- `createdAt`: set automatically by Hibernate when the row is created.

Lombok annotations generate boilerplate constructors, getters, setters, and related methods, although some DTO classes in this module use handwritten accessors instead.

### `SecurityConfig`

Spring Security configuration.

Beans:

- `PasswordEncoder passwordEncoder()`: returns `BCryptPasswordEncoder(12)`, used by `UserService`.
- `SecurityFilterChain securityFilterChain(HttpSecurity http)`: disables CSRF, permits register/login, and requires authentication for other local endpoints.

In this system, most request authentication happens in `api-gateway`. This local security chain still defines the direct-service behavior if the service is called without the gateway.

### `JwtUtil`

Token creation helper.

Responsibilities:

- Reads `jwt.secret` and `jwt.expiration` from config.
- Base64-decodes the shared secret.
- Creates an HMAC signing key.
- Builds JWTs with:
  - subject = user email
  - `userId` claim
  - `role` claim
  - issued-at timestamp
  - expiration timestamp

The gateway later validates these same tokens and forwards selected claims as request headers.

### `RegisterRequest`

Request DTO for registration. Carries `email`, `password`, and `role` from the HTTP request body into `UserController` and `UserService`.

### `LoginRequest`

Request DTO for login. Carries `email` and `password`.

### `LoginResponse`

Response DTO for successful login. Contains the signed JWT token.

### `UserResponse`

Safe response DTO for registration. Contains `id`, `email`, and `role`; it deliberately does not expose the password hash.

## How Classes Interact

Registration flow:

1. `UserController.register(...)` receives JSON as `RegisterRequest`.
2. `UserService.registerUser(...)` validates the request.
3. `UserService` calls `UserRepo.findByEmail(...)`.
4. `UserService` uses `PasswordEncoder` from `SecurityConfig`.
5. `UserService` creates and saves a `User`.
6. `UserService` returns `UserResponse`.
7. `UserController` returns HTTP `201 Created`.

Login flow:

1. `UserController.login(...)` receives JSON as `LoginRequest`.
2. `UserService.loginUser(...)` loads the `User` by email.
3. `PasswordEncoder` verifies the password.
4. `JwtUtil` creates a signed token.
5. `LoginResponse` returns the token to the client.

## External APIs And Framework Types Used

- `JpaRepository`: Spring Data JPA repository interface that generates CRUD behavior and query methods. Official API: [JpaRepository](https://docs.spring.io/spring-data/jpa/docs/current/api/org/springframework/data/jpa/repository/JpaRepository.html).
- JPA annotations such as `@Entity`, `@Table`, `@Id`, `@GeneratedValue`, and `@Column`: map Java objects to database tables. Official API: [Jakarta Persistence API](https://jakarta.ee/specifications/persistence/3.2/apidocs/).
- `@CreationTimestamp`: Hibernate annotation that populates a timestamp when an entity is inserted. Official API: [CreationTimestamp](https://docs.jboss.org/hibernate/orm/current/javadocs/org/hibernate/annotations/CreationTimestamp.html).
- `PasswordEncoder` and `BCryptPasswordEncoder`: Spring Security password hashing API and BCrypt implementation. Official docs: [Password Storage](https://docs.spring.io/spring-security/reference/features/authentication/password-storage.html).
- `SecurityFilterChain`: Spring Security interface that defines which filters apply to a request. Official API: [SecurityFilterChain](https://docs.spring.io/spring-security/site/docs/current/api/org/springframework/security/web/SecurityFilterChain.html).
- `Jwts`, `Decoders`, and `Keys`: JJWT APIs used to create signed JWTs. Official project docs: [JJWT](https://github.com/jwtk/jjwt).
- Lombok annotations such as `@Data`, `@NoArgsConstructor`, and `@AllArgsConstructor`: generate boilerplate code at compile time. Official docs: [Project Lombok Features](https://projectlombok.org/features/).

## Notes On Unused Imports

`UserController` imports `GraphQlProperties`, and some DTOs import Lombok annotations that are not used in the current source. These imports do not affect runtime behavior and can be removed later as cleanup.

## Configuration

Local `application.yml` imports config from `config-server`.

Central config includes:

- PostgreSQL datasource for `auction_db`.
- Hibernate `ddl-auto: update`.
- Kafka bootstrap server.
- Eureka registration.
- JWT secret and expiration.
